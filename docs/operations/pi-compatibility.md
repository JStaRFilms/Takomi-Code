# Check a Pi release for CLI session continuation

T3 Code starts Pi for normal turns, but **Continue CLI session** also reads Pi's session files. That part needs a separate compatibility check. The server advertises session listing, attach, and fork only when the configured Pi executable reports a version in [`PI_CATALOG_VERSIONS`](../../packages/takomi-pi-host/src/sessionCatalog.ts). The [command palette](../../apps/web/src/components/piContinue/piContinue.logic.ts) hides the action otherwise. This is an exact allowlist, not a minimum version: older listed releases remain supported when a new one is added; other older and newer releases are not assumed compatible. A listed executable is still insufficient for an individual file with an unsupported header: attach and fork require session format v3.

When someone updates Pi or reports that the palette action disappeared:

1. Check the **configured** Pi provider instance's binary path and run that binary with `--version` in its environment. The server may use a different executable from the `pi` on your own `PATH`. Check that the provider is enabled and its probe can read the version. Do not infer compatibility from the package version in this repository.
2. Compare the new Pi release's session implementation with the [bounded scanner](../../packages/takomi-pi-host/src/sessionCatalog.ts) and [file checks](../../packages/takomi-pi-host/src/sessionInspect.ts). Verify the default directory encoding for a workspace, `--session-dir` / environment / settings precedence, JSONL filename and header fields, session format version, and the [fork layout](../../packages/takomi-pi-host/src/sessionFork.ts). Check the RPC commands used to resume a session in the [adapter](../../apps/server/src/provider/Layers/PiAdapter.ts). Do not add a version just because `pi --version` succeeds or its semver is newer.
3. If anything changed, adapt the reader or resume path and write focused tests against fixtures from that release **before** allowing it. Do not open a live user's session with a writable Pi process to test discovery; use disposable fixtures. If the conventions are unchanged, add the exact version to `PI_CATALOG_VERSIONS`. The [server capability check](../../apps/server/src/provider/Layers/PiProvider.ts) uses that same list; do not add a second list there. Keep previously verified versions unless a real incompatibility is confirmed.
4. Cover the release in the [scanner tests](../../packages/takomi-pi-host/src/sessionCatalog.test.ts) and [provider tests](../../apps/server/src/provider/Layers/PiProvider.test.ts). Run the focused catalog, fork, attach, and palette tests. From the repository root:

   ```sh
   node --experimental-strip-types --test packages/takomi-pi-host/src/sessionCatalog.test.ts packages/takomi-pi-host/src/sessionFork.test.ts packages/takomi-pi-host/src/sessionHistory.test.ts
   vp test run apps/server/src/provider/Layers/PiProvider.test.ts apps/server/src/provider/Layers/PiSessionCatalog.test.ts apps/server/src/provider/Layers/PiSessionAttach.test.ts apps/web/src/components/piContinue/piContinue.logic.test.ts
   ```

5. Update the version requirement in [user guidance](../user/cli-continuity.md) and the supported-release notes in [provider documentation](../features/takomi-pi-provider.md). Verify listing and continuation against a disposable v3 session using the same configured binary. Check that an unsupported release still hides the palette action and that an older verified release still advertises it. Do not use the developer's live Pi session directory for a test run.
