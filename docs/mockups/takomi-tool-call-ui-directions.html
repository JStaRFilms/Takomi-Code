Takomi Tool-Call UI Design Directions

Visual Mockup comparison for Phase 0 visual direction gate (feat/takomi-tool-call-ui)

Strengths and Tradeoffs Summary Matrix

Metric Direction A: Inline Chronological Log Direction B: Grouped Structural Block Cards Direction C: Split-Pane Workspace Inspector
Visual Footprint Compact by default, but stacks vertically in the thread as tools run. Medium-large. Groups related steps into a single unified card in the thread. Extremely compact in chat stream. Details are loaded in the secondary pane.
Disclosure Paradigm Accordion disclosures inline inside the chronological thread. Accordion sub-sections inside the card block boundaries. Click timeline row to load/focus that tool's state in the inspector pane.
Strengths & Pros Chronological Context Low Integration Cost

Maintains strict temporal logs relative to surrounding chat answers; feels familiar to users accustomed to traditional log output.

High Scannability Context Isolation

Binds subagent pools, policies, and board progress into a unified visual workspace component. Easy to see what is currently active.

Zero Chat Bloat Deep Inspect Panel

Keeps the chat flow highly readable. Perfect for review tasks, displaying large code diffs, or detailed subagent state trees without scroll-jank.

Weaknesses & Cons High Thread Noise Hard to Track Overview

Intense parallel tasks (e.g. 5 subagents running concurrently) generate a huge wall of logs, pushing actual chat content off-screen.

Stream Interruption

Breaks the linear stream metaphor. Updating older cards with new logs changes visual state out of chronological order.

Context Splitting High Interaction Cost

Forces the eye to jump between left and right panes; requires user click interaction to view details that would otherwise be inline.
