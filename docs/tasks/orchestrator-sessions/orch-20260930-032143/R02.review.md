## Confirmed defects

### Late correlated notices take the currently active turn ID

`PiAdapter.ts:2209-2220` and `2553-2558` correlate a pending prompt but call eventBase(context), which takes the currently active turn rather than pending.turnId. A's command can start independent work, its native run settles while its async handler remains pending, then B starts before A throws/acknowledges. A's failure notices become B's persisted work-log activity. With no current run they lose the originating turn association.

Native source supports async command handlers and independent sendUserMessage work. `ProviderRuntimeIngestion.ts:601-626` persists event.turnId directly, so requestId metadata does not fix ownership. Associate correlated outcome/error notices with pending.turnId even after it settles; do not reopen terminal turns or stop B. Add controlled process-path delayed A error/acknowledgement while B is running, including persisted activity ownership proof.

### Explicit malformed disposition consumes pending correlation and strands idle turn

`PiAdapter.ts:2197-2208` removes a matching pending prompt before validating explicit disposition. success=true with disposition='unexpected' or null produces neither outcome nor completion. Idle command remains running; later corrected response is ignored because the pending ID was removed. This is not the documented legacy case with absent disposition.

Validate before consuming correlation and produce a correlated protocol failure or another deterministic idle settlement without terminating unrelated native work. Test malformed response followed by corrected/duplicate acknowledgements using peer drain/receipts, not sleeps. Preserve legacy absent-disposition handling.
