## Findings

### 1. A real command-only lifecycle gap precedes the rest of parity work

`PiAdapter.ts` creates an active T3 turn before sending prompt. Its successful response settlement is restricted to the tracked Vault prompt ID. General disposition is not read. `/takomi-status` only notifies in canonical `takomi-runtime/commands.ts:308-312`, so Pi 0.99.1 returns handled without an agent run and the adapter has no general completion path.

Native `rpc-mode.js:298-317` emits success after prompt preflight. `agent-session.js:1448-1566` distinguishes started, queued and handled. The latter does not guarantee no model work. Canonical routing at `commands.ts:230-231` calls sendUserMessage to start independent review work. Native command exceptions emit extension_error and still report handled; the current adapter does not turn a matching general command error into a failed command outcome.

Required fix is correlated submission state plus run state. Test no-run handled, input-handler consumed input, handled before/after independent agent_start, queued/started, error, duplicates and stale generations. Do not complete any active run solely on handled. Do not copy the Vault wildcard into a larger slash-name wildcard. Retain private Vault logging/one-use settlement.

### 2. The compatibility baseline is red and mixes frozen/native checks

`PiProtocolConformance.test.ts:378` expects installed probe version 0.84.4, while explicit installed metadata reads 0.99.1 and the catalog supports it. Framing and synthetic peer tests are frozen 0.84.4 fixtures. Installed declaration probing and public SessionManager copy/append/reopen are installed-native integration checks. They must have separate attribution.

Parent-provided baseline was 110 passes and 2 failures in eight suites. Standalone rerun passed copied-fixture continuation but failed the installed 0.84.4 assertion. G01 did not rerun tests. The mixed-run-only native failure cause remains unknown; neither concurrency nor timing is established. A version-string update alone is not compatibility proof.

First Build is S0: narrowly repair test attribution and preserve operation/declaration/native fixture assertions, then reproduce standalone and the original focused eight-file command. The exact eight filenames are absent from the master plan; the parent must retrieve the previous command. Do not fabricate exact reproduction.

### 3. Session continuation exists, but full session semantics do not

Catalog, fresh-thread original-file attach, file-copy fork, bounded text hydration, release and Sync are implemented in current server/web code. The user's successful Continue test is C1 user-reported manual evidence with client/build unspecified. It is not evidence for CLI-return, release, sync or mobile.

Production state stores sessionFile, imported file record positions and fuzzy role/text matching. It does not persist independent native append high-water and active leaf. Host history reconstructs the last-entry branch only with one root; valid multi-root sessions fall back to all records and can mix abandoned branches into visible history. Confirm with a disposable regression fixture before fixing.

Native get_entries/get_tree expose stable IDs and current leaf. Public AgentSession.navigateTree and ExtensionCommandContext.navigateTree exist; the latter is bound inside RPC command context. Thus a narrow canonical extension command can navigate with hooks/context rebuilding without replacing the entire provider. There is no stock navigate_tree RPC. A file-prefix fork is not native user-entry fork, active-branch clone or tree navigation.

Original-file sequential attach is authorized. T3 reservations do not enforce a cross-process CLI lock. Concurrent writers remain unsupported; release-before-CLI and return-to-GUI proof stay required.

### 4. Extension state is lost even where native RPC supports it

Adapter handleUiRequest accepts notify and four dialogs. setStatus, setWidget, setTitle and set_editor_text return without projection. Canonical OAuth-router already emits string-array RPC widgets in `oauth-router/commands.ts:277-289`, so status/accounts/usage reports are discarded. Canonical runtime mode state and host sound status also use these methods.

Rich questions are partial: one question per native request, string labels reused as descriptions, no explicit Pi multi-select mapping, preview mixed into title prose and editor prefill rendered as question text rather than editable initial value. Existing shared schema/client code already supports generic multiSelect; the loss occurs before rendering. Terminal custom components remain genuinely native-limited and need declarative alternatives, not ignored functionality.

### 5. Suite-root resource loading omits canonical Vault

`PiLaunchResources.ts:8-15` lists six canonical extensions, not takomi-vault, then passes --no-extensions in suite mode. A global Vault copy may be included as a companion, which hides the omission on some environments. A suite-only setup cannot rely on it. The inferred-suite test fixture uses the same six names.

S2a should add Vault to the shared startup/discovery set and verify no duplicate global copy, without rewriting private input/transfer logic or editing/deploying the suite. Existing secret and transfer clients include native mobile implementations; do not rebuild them as if absent.

### 6. Displayed tools are not direct controls

Web/desktop semantic cards and inspector already merge boards, Todo and child activity. Buttons disclose/select details. They do not change mode, gate, task status or stop/resume an actual child. Mobile has generic work-log/task/question/Vault paths but no native Takomi semantic cards, inspector or Pi catalog/continuation UI.

Some existing /takomi handlers are deterministic and should be reused: mode/gate/stage/reset and subagent enable/disable/status. Routing text sends model review before a tool applies it, so that path is not deterministic apply. Suite-owned control/state APIs must preserve gate provenance, source scopes, authored board documents and actual controller transitions. G02 should identify these existing handlers before proposing new suite machinery.

### 7. Managed execution and utility generation remain undelivered

`packages/takomi-pi-host` has useful catalog/fork/history/provenance/ownership utilities. `host.ts` explicitly advertises only capability-probe and session not-opened; bin.ts serves probe/catalog. No long-lived public-SDK execution/control/UI host exists.

Managed installer/runtime integration, version/assets/license delivery and update ownership remain partial. Pi maintenance is manual-only. `PiDriver.ts:158-172` explicitly fails utility titles, branch names, commit messages and PR text. These need an isolated generation boundary, not prompts in the user's chat session.

Recommendation is existing RPC owner plus narrow public extension bridge, not immediate provider replacement. Packaging must reconcile current canonical 0.84.4/pi-subagents 0.31.0 pins with the target 0.99.1 installation and G02's actual dependency evidence.
