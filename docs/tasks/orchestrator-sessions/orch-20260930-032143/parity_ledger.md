## Correctness findings that govern completion

### Prompt submission and independent work are different facts

N-LIFE emits prompt success after preflight. A command handler is awaited; a consumed input or command returns handled without starting an ordinary prompt run. Errors inside `_tryExecuteExtensionCommand` emit extension_error and still return handled. EC `/takomi-status` only notifies. EC `/takomi routing <text>` calls `pi.sendUserMessage(reviewPrompt)` and can start independent work. A allocates a turn before sending prompt, but only binds Vault prompt IDs for successful command settlement. Other handled/no-run input leaves the turn running. General command errors are emitted but do not mark that turn failed.

A response must match generation and submission ID. Do not complete an active run merely because a handled response arrives. The completion strategy defines a submission/run settlement contract and tests for both event orderings. Querying get_state can observe present idle state; it cannot prove that arbitrary extension code will never schedule future work. No arbitrary sleep is a proof of command-only behavior.

### Compatibility tests mix reproducible fixtures with installed integration

T2 framing/decoder/synthetic-peer cases are reproducible 0.84.4 fixtures. The installed declaration test resolves Pi from PATH, then line 378 insists on 0.84.4; current installed package metadata is 0.99.1. Its exact RPC operation list check may remain useful, but must be bound to the intended installed-version contract rather than mislabeled as a 0.84.4 replay. The copied-fixture public SessionManager test writes only a temporary fixture. It checks opening/appending/reopening and branch/custom-entry preservation, not a real model continuation or client round trip.

Parent-provided baseline observation: eight suites produced 110 passes and 2 failures. Standalone T2 passed the native fixture continuation and failed the 0.84.4 assertion. The reason the native fixture failed only in the multi-file run is unknown. G01 did not reproduce it and does not attribute it to concurrency, timing, package resolution or cleanup.

### Active leaf and append high-water are not represented separately in production

A's resume cursor stores schemaVersion and sessionFile. S sync derives a watermark from imported record-position IDs and matches role/text counts plus long user-text containment. H history reconstructs the last-entry parent chain only when exactly one root exists. For multiple roots, cycles or a missing parent it returns all records. Multiple roots are valid native trees, so that fallback can display abandoned branches as active conversation. Write a disposable multiple-root/branch fixture before repairing it.

T2 separately has highWaterId and native leaf in its fixture probe, but the tested fixture makes them equal. That is not production state or divergent-leaf proof. Native get_entries returns entries after a stable append cursor and current leaf; get_tree returns roots/labels/leaf. Native `SessionManager.branch` can move its in-memory leaf without appending, and `AgentSession.navigateTree` runs higher-level hooks, context rebuilding and optional summary. It must not be replaced by file-prefix cloning or a raw SessionManager mutation. A restored file normally reconstructs leaf from entries, so in-process navigation and durable append position need explicit handling.

### The host is not a managed execution host

K verifies packed runtime provenance, selected dependencies, licenses/private-module hashes and owned files. Its probe declares only capability-probe and session not-opened. `bin.ts` serves read-only probe/catalog. Session catalog/fork/history utilities have grown beyond the probe, but there is no implemented long-lived SDK AgentSession execution/UI/control superset. Preserve these useful utilities; do not assume historical B00-B19 plans were delivered.

### Suite-root loading can mask Vault omissions

R's explicit extension list has six names and omits takomi-vault. Suite mode passes --no-extensions, then explicit paths. A globally installed Vault may enter via companion discovery, which makes the omission environment-dependent. A canonical suite-only setup cannot rely on that copy. T1's inferred-suite fixture also lists the same six extensions. Fix the shared list and both startup/discovery tests without changing secret handling or deploying the suite.

Final checks require the authorized test-t3-app/test-t3-mobile workflows, real configured environment/runtime versions, disposable sessions, an available native client/device, and separate installed-desktop verification.
