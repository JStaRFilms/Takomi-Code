## Transport and control decisions to carry into Design

Stock RPC supports keyed set/clear status, string-array widgets and editor-text updates. Their loss is an adapter omission. Project them as bounded, escaped, process/thread/environment-scoped state. Clear/replacement and reconnect behavior matter. Editor updates need initiating-client/draft conflict handling and must never auto-send.

Basic RPC dialogs cannot carry arbitrary terminal components. Rich questions need declarative descriptions, stable choice values, previews, multiple-question/multi-select semantics and editable prefill. Supply that metadata through a negotiated extension interface or preserve an explicit unsupported/cancel fallback. Validation belongs to the operation owner; secret redaction precedes server event/log/projection; cancellation settles once.

Existing `/takomi` commands cover some direct actions. A missing GUI state/control boundary may use typed versioned readState/apply with expected revision, authoritative result, idempotent request IDs and explicit validation/cancellation. Only expose run controls for actual supported controller actions. Do not invent stop/resume methods or ask a model to execute a button press.

Tree navigation can use the public command-context navigateTree API through a narrow suite command inside the same Pi owner. That is not a stock navigate_tree RPC, and file-prefix cloning is not active-leaf navigation.
