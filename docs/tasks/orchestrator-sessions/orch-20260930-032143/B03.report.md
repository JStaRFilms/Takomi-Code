# B03 report: suite-root Vault loading

## Change

Added `takomi-vault` to the canonical suite resource list used by explicit roots, inferred-suite completeness checks, discovery, and session startup. In suite mode, companion discovery now drops candidates whose path identifies one of the canonical Takomi extensions. That closes duplicate loading through configured global extension paths and npm package manifests as well as the existing global `extensions/` scan. Non-Takomi companions such as `pi-web-ui` remain in the launch args.

The test fixtures now represent all seven canonical extensions. Resolver coverage checks suite-only loading with an empty agent home, inferred loading, exactly one suite Vault path despite global directory/configured/npm duplicates, preservation of the unrelated web UI companion, and the existing `allowInferredSuite: false` trust behavior. An incomplete configured root reports the missing Vault path; discovery keeps returning its existing `unavailable/failed` result. A synthetic adapter session captures actual Pi launch args and confirms the suite Vault path appears exactly once.

Private Vault input, transfer opt-in flags, and command settlement were not changed. Existing synthetic private input/export and Vault command tests passed. No canonical suite files, real secrets, or live sessions were touched.

## Red-first evidence

Before adding Vault to the canonical resource list, ran:

`vp test run apps/server/src/provider/Layers/PiProvider.test.ts`

It failed at the new resolver assertion: the inferred resource args contained zero suite Vault paths instead of one. This reproduced the omission. After the change, the complete focused run passed.
