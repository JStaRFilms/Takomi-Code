## Delivered

Each client constructs one `createEnvironmentExtensionStateAtoms` helper from its existing connection atom runtime, environment thread shell atoms and environment config atoms. Header and composer consumers share its thread-scoped family and underlying B05 subscription. No component creates a separate stream or global extension store.

The confirmed support-gate defect was in the shared helper. It used `modelSelection.instanceId`, which can describe a future model, instead of `session.providerInstanceId`. It now follows the same owner-first fallback used by the existing mobile provider-instance helper. Support still requires explicit capability metadata in the owning environment. A cached active snapshot from another provider instance is withheld while the new owner publishes. The B05 supervisor-session stream and server lifecycle were not changed.

A shared read-only presentation atom excludes editor suggestions, suppresses inactive content, separates above/below widgets, and labels unknown support, unsupported providers, waiting, disconnected and last-known text. Truncation and overflow produce a visible omission notice outside collapsed output. Exact native keys remain intact. Entry identity includes environment, thread, owning instance, process generation, entry kind, exact key and exact content. Unrelated status changes retain an open disclosure; replacement, clearing, process generation or environment changes do not resurrect its detail.

There is no local hide or dismiss action. Closing a disclosure closes only its local detail. The current entry remains reachable, and no native clear RPC is sent. Text is rendered as text, with preserved bounded line breaks and no HTML, Markdown, links or automatic opening.
