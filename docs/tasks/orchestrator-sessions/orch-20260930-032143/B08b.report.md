## Delivered

`provider.getPiSessionStats` is a typed unary read with thread ID and expected provider instance. Authorization requires orchestration read scope. The WebSocket handler checks thread existence before and after the read and returns a bounded, generic error rather than provider details. Mutation scopes are unchanged.

ProviderService resolves the existing binding with `allowRecovery: false`, requires the live Pi owner and expected instance, and rechecks the exact registry adapter wrapper and binding before returning. PiAdapter captures its exact context object, local process generation and existing opaque extension lease. It checks native process liveness before the request, after the response and immediately before returning. Stopped, replaced, wrong-instance and fenced processes cannot supply a current result. The read does not start or recover a provider, open a session file, send a prompt, or emit an orchestration event.

### DTO and privacy

The DTO contains thread, owning instance, opaque process generation, fetch timestamp, `pi-native` source and `all-session-entries` scope. It carries message counters, cumulative token counters, native-reported USD cost and nullable native-estimated context. Counts must be safe nonnegative integers; cost and percentage must be finite and nonnegative; context windows must be positive safe integers. Zero is retained. Missing required statistics and malformed fields fail rather than becoming zero.

Schemas discard extra fields at every selected level. Session paths, native session IDs, raw model objects, details, summaries, credentials and conversation records are excluded. The R08b correction intercepts statistics IDs or commands before setter dispatch, native logging and generic handling, regardless of claimed record type. Only a matching live pending statistics read receives the record for schema validation. Late, interrupted, unmatched and command-only statistics frames are discarded without retaining ID history. Correlated records cannot become lifecycle events or widget/editor updates. No statistics event, persistence table, journal or mutation receipt was added. The existing 1 MiB JSONL ceiling remains intact.

Pending RPC cleanup now runs on interruption as well as normal completion. This is needed when clients close details or change source during a read.

## Clients and entry points

One shared atom family uses the existing environment RPC request and runtime machinery. Its key includes environment and thread. At intent it captures the active owner, advertised support, exact native lease generation and supervisor transport session. Changes interrupt the old request and late results are discarded. The response must match the captured thread, instance and process generation.

Opening details fetches once. Refresh is ignored while a read is pending. Reconnect fetches once only while details remain open. Source equality prevents unrelated shell/model/extension updates from triggering another request. There is no polling, timer, background statistics scan or per-render request. Disconnected or failed refresh output is labeled last known. Inactive or replaced owners cannot authorize another read from cached output.
