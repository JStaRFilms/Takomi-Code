# B09b bounded-confirmation correction

R09b's confirmed blocker is corrected. A connected client no longer keeps its local native-input slot busy forever when resolution persistence fails. Ready for the same reviewer's original reproduction and focused follow-up. No broad reimplementation or new review was launched.

## Scope and behavior

Only these existing deliverables changed for the correction:

- `packages/client-runtime/src/state/piInputSubmission.ts`
- `packages/client-runtime/src/state/piInputSubmission.test.ts`
- `docs/features/takomi-pi-provider.md`

The original 64 owned paths remain the implementation boundary. Report, manifest and recovery/task notes are uncommitted work artifacts. Web, inherited desktop and native mobile controls already use the shared pending state, so they need no separate implementation change.

The fixed 60-second local window starts after the RPC confirms durable recording. It uses the existing Effect clock and the mounted resource scope. Native acknowledgment and RPC deadlines, JSONL and attachment caps remain unchanged. No polling, configuration layer, retry or replay was added.

Expiry releases only the matching local pending slot and clears its consumption callback. It does not resolve durable history, claim acceptance/rejection, mutate a draft or send another request. The existing authored row remains unconfirmed and its text, images, files and context stay recoverable. The visible message says local confirmation ended, native acceptance remains unconfirmed and submitting again may duplicate work. Server ownership and busy checks still apply to any new explicit request.

Each operation owns its own timer. Terminal outcomes, failed recording, listener termination, source replacement, disconnect, unmount and disposal release the operation and interrupt only its timer. Releasing an old operation cannot cancel a newer request. Timer expiry checks the exact operation and source, and cannot overwrite an already known outcome or a newer pending request. Consumption references are nulled on release or expiry, not retained by completed timers. Effect removes completed forkIn children from the owning scope.

A late immutable terminal event may update the most recent unconfirmed client record and normal authored history, but there is no expired callback left to consume. Old outcomes cannot overwrite a newer pending request. Known native outcomes just before expiry remain authoritative and cancel the timer.
