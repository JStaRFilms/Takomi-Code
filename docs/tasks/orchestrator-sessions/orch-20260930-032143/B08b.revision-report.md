## Reproduction and fix

The response-type-only branch let an actual statistics request ID with `type: agent_start` reach generic event handling. It created `turn.started` with private fields in its raw payload and canonical log. Setter-shaped records bypassed it even earlier and changed widget/editor state.

I added nine cases to the existing controlled process/driver/registry/ProviderService fixture before changing the adapter. The fixture exposes the actual statistics request ID through its existing Deferred. Cases combine `agent_start`, widget and editor setters with pending, interrupted and settled reads. Every case emits three identifiable records:

- The actual statistics request ID, without relying on a statistics command field.
- An unrelated ID with `command: get_session_stats`.
- An unseen statistics-prefixed ID, which proves suppression does not need retained history.

Payloads contain valid numeric statistics plus synthetic `/private/review-stats.jsonl` and `REVIEW_PRIVATE_STATS` markers. Startup and subsequent input events drain the real canonical logger before assertions. The tests check runtime events, native records, canonical records and the complete extension snapshot. They also answer genuine subsequent input and complete a normal native turn.

The adapter now checks statistics identity at the decoded-record boundary, before setters, native logging, missing-type handling or generic native dispatch. A matching pending statistics read on the exact live context receives the record. Its existing response schema rejects a wrong type and returns `Pi returned invalid session statistics.` without a raw cause. Command-only, unmatched, interrupted and settled frames are discarded. No ID history was added.

Pending response Deferreds now hold decoded JSON records rather than asserting a string `type` before validation. This avoids adding a cast for malformed records. Other RPC handling is unchanged. The obsolete response-only statistics branch was removed; the existing native-log privacy guard remains.

No parser redesign, version expansion, UI/control, DTO or client change was made. The other 34 feature deliverables were preserved.
