# D01 all-client interaction contract

Parent synthesis of the synchronous designer handoff. These are approved implementation requirements within the user's all-client functional-parity mandate, not client verification evidence. The full designer return remains in the session conversation. No designer code/files/tests/builds/clients were executed. Keep backend interface selection in architecture, not this design document.

## Existing UI and authority

Reuse web/desktop ChatView, composer command menu/palette, existing pending-input/private-input panels, MessagesTimeline, TakomiToolCallCard/Inspector, PiContinueDialog/PiSessionMessages/PiSyncGate, ContextWindowMeter and provider Settings. Mobile uses ThreadComposer/ComposerCommandPopover, PendingUserInputCard/PiSecretInputCard, ThreadFeed/thread-work-log/ThreadTasks, native settings rows, sheets and detail navigation. Preserve the existing design system and responsive behavior; no new dashboard or continuous animation.

Every operation targets its thread's owning environment/provider instance, not the Settings selection on another device. Existing authenticated scopes govern mutation and maintenance. Pi owns execution/native context, Takomi owns its runtime/board/routing/children, T3 owns remote projection and local drafts. Show confirmed/pending/cancelled/failed/unavailable/disconnected states. Last disconnected snapshot is stale and cannot authorize mutations. Uncertain network outcome means checking, not blind resubmission. Capability-gate controls and offer honest supported alternatives.

## 1. Command result and model-run lifecycle

Command output is a bounded work-log result/notice with severity and command identity, not fabricated assistant text. Typed commands and discovered composer/palette/mobile entries share semantics. Track submitted prompt acceptance/disposition separately from actual model-run liveness. Handled may finish a submission without finishing independently started work; started/queued acknowledgements are not completion. A rejected input or correlated extension failure remains failed even if a later handler acknowledgement says handled. Uncorrelated notices stay labeled extension notices.

Edit/retry restores the original command as an unsent draft. Local dismissal does not undo execution. No checkpoint/restore controls without actual checkpoint evidence. Acceptance: idle `/takomi-status` settles once; the same command during an active run does not stop that run's indicator; routing review's independent model run stays visible until native settlement. Check all three clients, not just adapter events.

## 2. Steering, follow-up and Stop

Running composer offers Steer now and Follow up when finished; queue count opens separate ordered native steering/follow-up lists and confirmed all/one-at-a-time modes. Mobile uses a send menu/queue sheet. Distinguish native queue from local waiting drafts. Extension commands use prompt, never steer/follow_up commands.

Stock RPC cannot atomically edit one queued item. Return queued messages to editor clears both queues and retains native-returned order/type as held drafts for explicit edit/resubmit. Clear before abort; recover text without silently overwriting any client's unsent draft or auto-sending. Known submitted attachments may be retained, but clear_queue's text-only result cannot promise attachment recovery. Clear/consume races restore only actual returned items. A clear failure warns queued work may remain; release-process fallback has a separate label. Stop does not undo files or promise to kill detached children.

Acceptance: two-client queue/mode visibility; mobile Stop while desktop has unsent text; held drafts remain recoverable and no cleared native queue restarts model work.

## 3. Compaction, retries, bash and stats

Native manual compaction is reached through the context meter, thread actions or palette with optional multiline instructions. Reuse each provider's actual capability; Pi uses compact RPC, not a model prompt containing terminal `/compact`. Show progress/result/cancel/error and estimated versus native token counts; do not promise undo. Auto-compaction toggle reads native state and turning it off does not silently cancel current compaction.

Retry shows native attempt/backoff/sanitized cause as waiting, not active generation. Abort retry is distinct from process stop and from auto-retry toggle. Unknown toggle readback stays unknown.

Direct Pi bash is a dedicated explicit shell action showing environment/workspace and inclusion in next model context, selected by default to match native behavior. Stream bounded output and final exit/cancel/truncation flags. Abort bash stops that shell, not the whole session. Excluded output still belongs to native history; included output enters the NEXT prompt. It is not the T3 terminal or a model-selected tool.

Stats separate cumulative billing from current context. Null context after compaction means unknown until next response, not zero. Mobile uses native detail sheets. Acceptance checks instructions/cancel/toggles/backoff and included/excluded disposable bash output on the next prompt.

## 4. Extension state and editor suggestions

Keyed status/widget state replaces by key and clears when native content is omitted. Preserve line breaks/placement using bounded text-only rendering with terminal escape removal, never HTML. Small status is near the composer/header; long widget content opens detail in web inspector or native mobile detail. Local hiding differs from native clearing. Reconnect restores current bounded snapshot; process replacement invalidates old ephemeral state and waits for new publication. Runtime title is a subtitle, separate from manual thread/native session names and global desktop title.

Designer proposed bounds, to be reconciled with existing contracts by the builder: 32 status keys, 16 widgets, 100 lines/widget, 2000 characters/line, 128 KiB aggregate. Bounds must visibly signal truncation; do not add gratuitous limits where a shared existing bound suffices.

Editor updates target the initiating client and originating draft revision. Apply only to an unchanged draft; otherwise offer preview/confirmed replace/insert/dismiss. Other clients receive suggestions, not mutated drafts. Unattributed updates are suggestions everywhere. Never auto-send. Acceptance includes keyed replacement/clear, multi-device reconnect/process replacement and competing unsent drafts.

## 5. Rich questions, editor prefill and private input

Use existing question cards. Stock RPC returns exact native option string/boolean/text; multiline editor starts with actual editable prefill, not question prose. Negotiated rich requests preserve stable question IDs/choice values, distinct descriptions, bounded preview, multi-select and multiple questions. Back/Next retains answers; final review/submit is explicit. Duplicate display labels never replace stable values. Owner validation leaves request pending with field-local error and retained safe answers.

A basic sequential fallback is labeled and usable only if the owner preserves required semantics. Otherwise show unsupported/cancel rather than silently turn multi-select into single-select. Cancel/timeout/replacement/other-device answer settles once; collapse is not cancellation. Private Vault cards/transfers remain separate from generic persisted answers, drafts and previews. Existing archive bounds remain unchanged. Failure requests fresh private entry, not redisplay of a retained secret.

Acceptance includes descriptions/duplicate-label values/previews/multiple questions/multi-select, validation retry, multiline prefill/cancel and cross-device/private cancellation races.

## 6. Deterministic Takomi control

Historical tool cards remain observations; current authoritative controls belong in inspector and native board/run detail with useful inline summaries. Reuse existing deterministic `/takomi` mode/gate/stage handlers. Separate stage selection, workflow preview and actual running work. Gate labels preserve native alias semantics and user provenance; auto-launch requires explicit user authority. Reset confirms consequences and reads defaults; it is not guaranteed undo or child shutdown.

Boards use supported task transitions/checklist changes with reopen/uncheck and authored-packet validation. Routing separates advisory text from executable configuration and exact provider/model IDs; preview precedes explicit Apply, cancellation writes nothing, stale revision requires refreshed review without losing proposed input. `/takomi routing <text>` that starts model preservation review is labeled model review, not direct apply.

Only genuinely supported handlers expose deterministic skill/policy load and context/prerequisite refresh. Discovery is not loaded-state proof. Child launch preview includes exact model/agent/thinking/cwd/context/worktree/single/parallel/chain/async semantics. Child interrupt/resume controls require actual engine support and legal states; runtime display/controller state is not proof of a process-control API. Unknown liveness offers Refresh, not invented Stop. Disabling future subagents does not promise to stop current children.

Acceptance includes mode/gate cross-client readback, board reopen/uncheck, routing conflicts preserving authored inputs, cancelled launch preview, stable child selection and verified legal run-control transitions or honest unavailable state.

## 7. Native sessions and sequential handoff

Reuse Continue project/provider actions and palette; mobile gets native picker and header/session-detail actions. Show owning environment/provider, native name/modified time, compatibility and fidelity. Continue binds the original file to a fresh thread; Fork has explicit separate file/provenance and unchanged source. Existing-thread switch is separately confirmed with native veto semantics.

Session detail separates native rename from T3 title; stats, tree, fork, export and release are scoped actions. Tree shows active leaf/labels/abandoned branches and separates effective model context from all history. Native navigation previews target/summary options and preserves old branch on cancel/veto. It is not git restore. Native fork selects stable user-entry IDs and pages older entries; restored text is an unsent suggestion. Current file-prefix copy must not masquerade as active-branch fork.

Imported history is frozen. No historical request approval, rerun or running control. Mark missing images/tools/thinking and visible truncation. Native append high-water, active leaf and T3 file checkpoint are distinct. Current bounds stay explicit: 2000-file catalog ceiling, 64 MiB source, 1000 hydrated messages, 32 KiB text, current 100/500 preview tails. Load older must actually page older data.

Release waits for owning process shutdown and retains GUI history. CLI and GUI cannot concurrently write the same native file. Resume after CLI exit reconciles entries/branch before sending; Sync is idempotent. T3 reservations cannot guarantee an independent CLI writer is absent. Export delivers actual authorized bytes to browser download/desktop save/mobile file-share, not a host path. No destructive delete is assumed available.

Acceptance uses disposable branched/compacted sessions, deep selection/native forks/navigation/remote export, release/CLI append/exit/mobile resume and repeat desktop sync, confirming active branch, no duplicates and unchanged fork source.

## 8. Auth, diagnostics and terminal equivalents

Provider Settings target the owning environment. Native Pi login/logout requires a supported owner API; until available provide explicit release/use-CLI/refresh rather than send terminal `/login` to a model. OAuth reports reuse widgets; aliases/status omit credentials and usage names cached/local/provider provenance and refresh time. Supported login/relogin is initiating-client-owned, callbacks end at the same environment, other devices see only pending state. Cancel/timeout invalidates pending flow and refreshes native status. Logout consequences are explicit. Account deletion/migration/publishing is not authorized.

Diagnostics separate discovered/loaded resources, unknown/partial trust, reload/catalog refresh and advisory/executable routing. Show binary/runtime/suite/subagent versions, managed/external ownership and compatibility evidence. External overrides remain manual; managed replacement cannot change an active leased runtime. GUI appearance differs from terminal themes. Palette/configurable keybindings map semantic actions; mobile gets buttons, not raw terminal keystroke forwarding. Host sound and client notifications remain distinct.

Vault plaintext reveal and arbitrary custom terminal components stay explicit terminal-only alternatives unless a safe supported declarative interface exists. No secret display or automatic report publishing.

## Implementation order and verification

First repair command outcome versus runtime activity without changing unrelated provider behavior, then keyed extension state. Native controls and rich forms follow architecture-selected contracts and capabilities. Mobile follows each shared slice rather than being silently deferred.

Known prerequisites: suite runtime compatibility, actual engine run-control APIs, safe native auth access and available client targets. Integrated proof needs real web/installed desktop/mobile clients and remote/two-device scenarios. Built-in Browser tools are absent and mobile targets are not yet established. No static render/source check counts as a client round trip.
