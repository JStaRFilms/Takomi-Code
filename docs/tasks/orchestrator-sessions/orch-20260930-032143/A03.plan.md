# A03 selected extension-state delivery

Architect conversation a039d6c4-8192-4e87-9c1e-dd294daeb505 returned read-only source analysis. Parent selects direct ephemeral publication at the adapter boundary instead of A02's proposed runtime-event ingestion. All state, privacy, draft and client requirements from A02 remain.

## Why direct publication

PiAdapter's runtime event queue is unbounded. ProviderService's old forwarders identify instance/provider rather than actual adapter/process identity and rely on scope closure to terminate. Ingestion adds another serialized worker. Persisted bindings are written after adapter startup, including recovery, so they cannot authorize startup widgets before session.started. Moving snapshots through these queues would still require new generation ownership and could accumulate large frames. B04 durable notices remain on their existing route.

There is no existing authoritative process-generation route API. Registry instance/adapter resolution and persisted session bindings are not that API. Actual Pi process authority is its sessions map identity, numeric generation, stopped flag and output fence.

## New minimal ownership contract

Create a scoped publisher identity per Pi adapter construction and associate it with the actual adapter object ultimately resolved by the registry. ProviderService is the only authority allowed to reserve a thread for that publisher before starting the adapter. Check current registry adapter identity, serialize competing starts for that thread, and handle both normal/recovery startup call sites. A non-Pi replacement must invalidate prior Pi state too.

The adapter opens a lease with a new opaque generation after sessions.set and before stdout forks. The existing isLiveContext guard plus the current lease are required for writes. A publisher cannot reserve its own thread. Old queued/direct begin/update/end cannot regain ownership because the reservation and lease must still be current. Scope finalization retires the publisher and invalidates its reservations/leases. Same-instance rebuild gets a different publisher, and cross-instance replacement invalidates the old owner. Failed startup leaves empty inactive state; recovery that adopts a live context retains its lease.

End/fence/failed startup/natural exit after stdout drain closes the matching lease only. A late old close cannot clear a replacement. ThreadDeletionReactor invalidates ownership before stop cleanup, even if stopping fails. An open attempt following deletion must fail its old reservation, not resurrect the topic. Snapshot subscription verifies thread existence through the current projection query path.

One service instance is shared below ProviderInstanceRegistryHydrationLive in server.ts and available to factories, ProviderService, deletion and ws. Service must not depend on its consumers. Avoid layer cycles or independent service copies. PiDriverEnv/options carry the publisher/controller; new names are proposed API, not existing source. Verify the registry returns the exact associated adapter or carries the association through any existing wrapper.

## Atomic latest-only stream

Use immutable complete replacement snapshots. In one service critical section, attach a scoped subscriber, capture its initial snapshot and allocate a capacity-one dropping queue of wake tokens. The stream yields captured state first, then consumes a wake token and reads current state under the same lock. Mutation and wake publication also hold that lock. A pending token coalesces repeated mutations. A mutation after capture yields another token.

No snapshot queue, unbounded PubSub or SubscriptionRef upstream. Each subscriber holds only initial/in-flight state and one wake token. Retain records only for live leases or active subscribers. End erases content and wakes inactive state. Final subscriber cleanup removes subscriber-only records. Delete sends empty terminal state and completes. No history/tombstone cache of every visited thread. Revisions are within a process generation; reconnect establishes a new baseline. Turn completion does not clear state.
