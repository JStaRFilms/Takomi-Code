## Implementation

One `ProviderExtensionState.layer` sits below registry hydration and the dependent server layers. Pi factories, the actual adapter registry, ProviderService, deletion and WebSocket handlers use that shared instance. Each approved fixture graph explicitly provides one real instance below its consumers. There is no noop/default extension service or per-consumer independent state.

PiAdapter publishes supported setters directly before raw logging and interactive dialog-ID validation. Startup opens its lease after `sessions.set` and before stdout forks, while the persisted session binding can still be absent. Nothing enters the runtime-event queue or durable extension-state dispatch. B04 notifications retain their existing route.

ProviderService captures a scoped start admission at entry, before its async lookups and per-thread queue. Normal and recovery paths reuse that exact token. Admissions, reservations and deletion share the mutation lock. Deletion revokes all outstanding active/queued tokens even without a topic, while keeping their original lane until its last admission releases. A later token uses that same lane and may succeed; no deleted-ID cache is retained. Reserve/open require the originating token to remain live and unrevoked. ProviderService checks the currently registered adapter identity and reserves its associated publisher. PiAdapter captures that reservation before startup awaits. Registry credential wrappers inherit the base adapter association, so the exact returned wrapper is the controller's authority. Service-issued leases use opaque generations and exact object identity. Replacement, failed startup, deletion and publisher retirement fence old open/write/end operations. A non-Pi start also invalidates old Pi ownership.

Verified live recovery adoption does not reserve or clear the existing lease. The queued operation validates its original admission before entering and before returning, so deletion during adoption also rejects its stale result. Scoped finalization removes admissions/empty lanes and abandoned unopened reservations, without clearing a valid live lease on successful completion. Turn settlement retains same-process state. Fencing, stop and drained natural exit clear it. Review found a binding-failure gap after native startup; normal and recovery binding failures now call `failStart`, as do provider-mismatch failures. Existing native lifecycle behavior is otherwise unchanged.

Subscription acquisition attaches the subscriber and captures immutable initial state under the mutation lock. Scoped acquisition registers cleanup, with projection reads remaining interruptible. Capacity-one dropping queues contain only `WAKE` tokens. The stream emits the captured initial snapshot first, then reads current state under the lock after each wake. Deletion sends empty terminal state to existing subscribers and removes the map entry; those subscribers cannot switch to a recreated thread. End/finalization removes ownerless subscriber-only records.

`provider.extensionState.subscribe` is thread-only, uses `observeRpcStream`, requires `AuthOrchestrationReadScope`, and checks projection thread existence. Missing/query-failed threads return a generic unavailable error. Clients cannot supply an owning instance or process capability.

Pi advertises optional `extensionState: "text-v1"`. Older Pi/server metadata remains unknown; other providers do not advertise it. The shared client atom family uses `ScopedThreadRef`, environment/thread keys and zero idle TTL. Only explicit support mounts the subscription. Tagged current supervisor-session identity and thread checks reject old callbacks. State distinguishes unsupported/unknown support, disconnected or stale retained data, and current snapshots including empty inactive state. RPC and session-switch buffering for this stream are both one.

No rendering, draft writes, suggested-text submission, manual/native thread renames, window-title changes, schema migration, new dependency or durable widget journaling was added. B06/B07 remain pending. Shared exports are sufficient; web/mobile RPC glue required no edits.

## Bounds and backpressure proof

- 32 statuses, 16 widgets, 100 lines per widget.
- 2 KiB UTF-8 per line and 16 KiB per status.
- Subtitle at most 4096 code points and 16 KiB UTF-8.
- Editor suggestion text at most 512 KiB UTF-8.
- Status/widget/subtitle text at most 128 KiB total.
- Exact, untrimmed keys at most 256 code points and 512 UTF-8 bytes; empty, control-containing and lone-surrogate keys rejected.
- Serialized snapshot at most 1 MiB, including JSON escaping. Later status/widget changes recheck editor/wire budget.

Replacement and clear remain possible at capacity. Missing status/widget content clears; empty strings and arrays remain valid. Placement defaults above editor and preserves below editor. Factories/objects are ignored. Terminal controls are removed and truncation preserves code points. Normalized duplicates do not increment revision. Editor IDs are generation-scoped data only. The existing native JSONL decoder retains its separate 1 MiB record rejection limit.

The service test holds a consumer through 500 writes and receives only the latest update, verifies initial-snapshot immutability and the post-capture wake, and checks cleanup after 100 subscriber-only visits. Another barrier test queues a mutation during verification and receives initial revision 1 followed by revision 2. Canceled/denied verification retains no record.

The real scoped WebSocket fixture holds the first client acknowledgement, performs 500 writes, then releases it. It receives exactly the captured initial snapshot and revision 501 containing `499`, with the same lease generation. Existing RPC acknowledgements and the socket output budget remain in force. There is no polling or added snapshot-history queue.

## Bounded-text performance correction

Parent verification subsequently found a 20-second timeout in the editor-first serialized-budget case. The default-only reducer rerun passed its six tests but took 19.61 seconds of test execution. Those results did not justify a higher timeout.

The narrow correction replaces only `clip`'s per-code-point TextEncoder/JSON.stringify allocations with indexed scalar, UTF-8 and JSON escape byte counting. Existing sanitation, caps, 1 MiB wire budget, aggregate accounting, flags, duplicate identity and immutable updates stay unchanged. The approved deletion admission code did not change. Two additional tests check exact/one-byte-short scalar and escaped JSON boundaries, title point counting, sanitation, immutable state and duplicate suppression.

Three pure reducer trials used the identical script before and after the edit. Median synchronous time for the 512 KiB newline editor plus 32 statuses fell from 24,591 ms to 578 ms. An individual status update with that editor fell from 1,596 ms to 17.5 ms. All trials retain exactly 1,048,512 serialized bytes and 392,692 editor code points. These are measurements, not flaky timing assertions. Full DTO JSON serialization remains the dominant sampled CPU work, so large synchronous setters are not claimed to be cost-free.

The final six-file focused selection passes all 64 tests without any timeout override or configuration change. All three original package typechecks pass. Owned lint still has exactly 25 baseline warnings and no new diagnostic. Owned formatting and diff checks pass. One earlier six-file run had an unrelated queued-start timeout across a large host time jump; its unchanged isolated case and full selection both passed afterward. The failed log and successful reruns remain documented separately in `B05.performance-report.md`.

The prior regression/RPC/capability counts above remain historical evidence, not newly rerun checks. The two inherited Windows-Claude failures remain an OPEN USER gate. No fix, waiver, skip or suppression was applied. Exact commands, measurements, CPU profile evidence and revision file scope are in the session-root `B05.performance-report.md`.
