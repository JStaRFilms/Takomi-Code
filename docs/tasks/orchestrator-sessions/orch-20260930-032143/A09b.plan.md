# Explicit native input plan

The user approved labeled authored-submission history entries in the existing timeline and full text, image, file and structured-context support. A09b.decisions.md records the interview and withdrawn ordinary-user-message proposal. This plan follows the architect's final source trace. It is a plan, not implementation or installed-client proof.

## Typed history without a false model turn

Define a feature-specific entry with request/thread/provider-instance/process-generation identity, steer or follow-up intent, original authored text, normalized ChatAttachment references, optional OrchestrationMessageContext, creation/update times and an outcome. Outcomes are unconfirmed, queued, handled, not-submitted, rejected or unknown. Reasons are bounded allowlisted codes. Never persist expanded host-path prompts, inline base64, raw native errors or extension-owned queue_update text.

Add server-only record and resolve commands with matching typed events. Record is the live execution intent. Resolve never triggers execution. They project to one stable activity ID derived from thread/request identity. The activity kind is pi.input-submission and turnId is null. Initial state is unconfirmed. Resolution changes only mutable status/time/reason, preserving original text, attachment ownership and timeline order. Only unconfirmed resolves. Conflicting terminal outcomes fail rather than rewrite history.

Do not call thread.message.user.append. It changes latest-user timestamps, ordinary send acknowledgments and response grouping. It also contaminates PiSessionSync text reconciliation despite not starting a provider turn. deferredTurn does not survive hydration.

## Existing storage and reliable hydration

ProjectionThreadActivities already upserts payload_json by activity_id. Server projector and shared threadReducer replace activities by ID. No new SQL table or migration is expected.

Add a direct typed activity lookup to ProjectionSnapshotQuery and its service interface. Match thread, deterministic activity ID and exact kind, then schema-decode the complete entry. OrchestrationEngine follows the existing durable lookup pattern before calling the pure decider. Startup command snapshots omit activities and running snapshots retain only 500, so in-memory activity scans cannot guarantee deduplication or resolution.

The resolution event contains the complete updated entry and original sequence. Projection, replay and clients can replace it without finding a prior page. Preserve original creation time to keep the row in the original pagination window. Each loaded row contains current persisted status. Do not pin every submission or scan unrelated pages.

ProjectionPipeline attachment pruning currently retains message/question-answer attachments but not these entries. Extend retention for typed submission attachments during revert, pruning and bootstrap cleanup. Thread deletion still deletes them. This is a prerequisite, not unrelated cleanup.

## Authenticated RPC and deduplication

provider.submitPiQueuedInput requires operate scope. Input contains requestId, threadId, expected owning instance/generation, intent and a message with original text, existing attachment/upload union and optional context. Response acknowledges durable recording through request identity and recorded sequence, not native acceptance. Existing thread events deliver actual outcomes.

Use deterministic record command identity and existing durable command receipts. Duplicate requests return the original record/receipt without another execution intent. Compare immutable submitted content. Reuse of an identity with different content conflicts. Cleanup newly claimed duplicate copies that the original entry does not own. Never replay submissions on reconnect, outbox drain, provider recovery or startup.

Preflight checks existing thread and captured supported native owner before recording. ProviderCommandReactor subscribes to the new record event on its existing hot stream only. Use the existing worker/drain architecture and bounded in-flight admission. Reject competing input rather than creating another native input queue. A settled receipt follows successful resolution persistence for controlled tests, not as production authority.

## Exact process and uncertainty boundary

Capture the original binding, wrapper, context, process and B05 lease. Validate expected generation and captured 0.99.1 support. After all preparation and routing awaits, use R09a-style captured validation. Immediately before admitting the encoded command to that context's stdin queue, synchronously check local context and exact current lease. Register the correlated Deferred before admission. Do not look up a replacement owner and submit there.

Use native steer or follow_up, not sendTurn. Do not recover/start a process, change model/thinking, create a turn or checkpoint, or generate a title.

Admission to stdin is the conservative uncertainty boundary. It does not prove native received bytes. After admission, write failure, timeout, cancellation, replacement or lost transport means unknown unless a valid correlated acknowledgment already established the outcome. Preserve known queued/handled acknowledgment even if the owner changes afterward. Persist resolution once. If persistence fails, leave unconfirmed and do not replay.

Use one pending native-input slot per context with the existing 30-second acknowledgment deadline. No indefinite detached waiter, request-ID tombstone history or automatic retry. Native queued acknowledges acceptance, not membership or immediate execution. Native handled acknowledges hook consumption, not independent model completion. Direct queueing does not start idle work, and a running agent may stop while hooks await.

## Attachment and context reuse

Extract the current Normalizer attachment block into a focused preparation function. Preserve input/count/byte limits, duplicate-ID checks, pending-upload claims, size/type validation, inline-image decoding, context-ID remapping and cleanup. Ordinary turn/input-response commands use the same extraction without changing behavior.

Reuse web upload preparation and mobile prepareTurnAttachments. Use projectComposerContextForProvider for structured context. Extract existing ProviderService provider-text preparation narrowly, including attachment path instructions and captured accessibility data. File references otherwise lack readable native contents. Host paths remain transient native transport data, never history payloads. Enforce the expanded-input limit as well as the authored-input limit.

PiAdapter reads normalized images and sends native image blocks. Direct native queueing skips foreground image resize/normalization. Current Pi model declarations do not advertise image support and hooks may change routing. Do not invent a client capability guarantee or silently discard images. Preserve them and report actual submission outcomes.

## Privacy and model lifecycle

Keep stats interception first, followed by queue-read interception. Intercept t3-pi-input-* before setters, logging and generic dispatch regardless of claimed type. Validate ID/type/command/success/disposition. Malformed acknowledgments mean unknown. Strip native error text from public results. Suppress late or unowned direct-input records without retaining request-ID history. Raw queue_update remains suppressed.

Ordinary B05 setters, questions and independent agent_start/model events still work. Submission outcomes cannot settle or retag B02 independent work. Never create pendingPrompts for these controls.

## Existing composer and timeline

Use small typed submission-row components in the existing web/mobile timeline, with original text, attachment previews, context and outcome. The row is not a tool lifecycle or normal user-message response boundary. Do not alter latestTurn/latestUserMessageAt, settled/snooze state, ordinary send acknowledgments or native-sync inputs. Unknown/unconfirmed is visible without an endless generation spinner or automatic Retry.

Add explicit native actions to existing web/mobile composer controls. Desktop inherits web. Ordinary Send, alternate-send, Settings defaults, local waiting queues and mobile outbox retain their behavior. Source capability uses actual live owner ahead of future model selection.

Capture editor/draft identity and revision, attachment/context state, route and generation. Only confirmed queued/handled may consume an unchanged originating snapshot. Concurrent edits, attachments, navigation and native revision changes preserve the current draft. Rejected/unknown keeps recoverable content without enrolling it in an automatic sender. History records authored input, not native transformed text or proven consumption. That fidelity remains incomplete until the native-history slice.
