# B05 bounded-text performance correction

Implemented the narrow correction in `B05.performance-revision.md`. The approved deletion admission fix is unchanged. Same-reviewer byte-accounting validation is pending. Two inherited Windows-Claude fixture failures remain an OPEN USER gate, with no fix, waiver, skip or suppression.

## Change

Only `clip` in `apps/server/src/provider/extensionState.ts` changed in production. It reads a code point by UTF-16 index, counts its UTF-8 bytes directly and advances by one or two code units. It no longer allocates an encoded byte array, a scalar substring or a JSON string per code point.

UTF-8 widths remain one, two, three or four bytes. Wire counting uses two bytes for quote, backslash and JSON's short ASCII escapes, six bytes for other C0 controls and lone surrogates, and the UTF-8 width otherwise. Slash and U+2028/U+2029 remain unescaped, matching JSON.stringify. Supplementary scalars consume one point and two UTF-16 code units. No scalar is partially included when its bytes exceed the remaining budget.

Caps, sanitation, aggregate accounting, full-envelope serialization, the 64-byte reservation, immutable replacement, duplicate suppression and flags are unchanged. No dependency, layer, batching, timeout/configuration change or broader refactor was added.

Two tests in `extensionState.test.ts` check exact fit and one-byte-short UTF-8 boundaries, supplementary title point counting and control/lone-surrogate sanitation. JSON wire boundaries cover ordinary ASCII, quote, backslash, slash, tab, newline, two/three/four-byte scalars and U+2028/U+2029. Those cases also verify immutable initial state, duplicate identity and the complete serialized limit. Existing meaningful cases and assertions remain intact. No test asserts elapsed time.

## Measurements

The pure Node script `.plans/b05-performance-measure.mjs` uses the real reducer and schema, a 512 KiB newline editor, then 32 valid 16 KiB newline statuses. It warms up 100 small setters, runs three trials, measures synchronous reducer calls with performance.now, and validates snapshots outside the timed interval. It also measures a small status, the initial editor, and a single status update with that editor already installed. The identical script ran immediately before and after the production edit on Node v24.16.0.

node --experimental-strip-types .plans/b05-performance-measure.mjs > .plans/b05-performance-before.json
node --experimental-strip-types .plans/b05-performance-measure.mjs > .plans/b05-performance-after.json
