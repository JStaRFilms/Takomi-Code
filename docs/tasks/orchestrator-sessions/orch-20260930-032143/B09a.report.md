## Privacy

Stats IDs still intercept first, before all setters, native logging and generic dispatch. Queue `get_state` requests use `t3-pi-queue-state-` IDs. Their frames go only to the matching pending read and schema validation, regardless of claimed command or event/setter type. A queue ID claiming `get_session_stats` reaches queue validation rather than waiting for timeout. Stats IDs still take precedence.

Late and interrupted queue-read IDs are discarded without ID history, logs, canonical events or setter updates. Raw `queue_update` is discarded before logging and normalization because its ordered arrays contain private text. The JSONL 1 MiB ceiling, B05/B07 direct setter publication and ordinary input/lifecycle handling are preserved.

The old 0.84.4 replay fixture contains one queue snapshot. Its existing log-count test now expects 30 instead of 31 and explicitly rejects any logged `queue_update`. The fixture and its version-only behavior are unchanged.
