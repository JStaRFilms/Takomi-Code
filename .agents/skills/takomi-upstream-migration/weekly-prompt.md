# Weekly upstream migration prompt

Use this prompt from a clean checkout of the last stable `Takomi-Code` commit. Do not copy an unfinished merge index from another machine. The skill's existing migration procedure and repository instructions still apply; this prompt supplies the weekly authorization and stricter boundaries.

> Perform the weekly upstream migration in this repository on `Takomi-Code` only. I authorize a timestamped backup branch, fetching upstream `main` and tags without replacing colliding fork tags, a normal merge, focused source verification, documentation corrections needed for this migration, and local commits. I do **not** authorize pushing, release artifact builds, publishing, deployment, browsers, dev servers, or live-state mutations. Do not touch `feat/pi-debrand` or parity worktrees.
>
> Before any write, confirm the exact checkout and branch, status, remotes, existing merge/rebase state, and concurrent work. If this is the wrong branch, changes are at risk, or another migration is active, stop and ask. Do not switch, reset, stash, discard, or duplicate active work. Create an immutable `backup/takomi-before-upstream-merge-YYYYMMDD-HHMMSS` from the original HEAD before fetching. Record both. Fetch `upstream/main` and tags safely; preserve existing fork tags when names collide. If already current, report a no-op. Merge normally, never rebase or force.
>
> Read both sides of every conflict and relevant tests. Preserve upstream architecture and stability fixes together with narrow Takomi/Pi features: branding and desktop identity/state paths, stable-only desktop updates, mobile identifiers/configuration, Pi session continuity and private input, host-authoritative updates, and local build sources. Prefer upstream's implementation where both sides meet the same need. Ask before ambiguous product choices. Do not reinstate an exact Pi package-version allowlist; validate installed-package and v3 session format/ownership instead.
>
> Audit against the backup and upstream, including conflict resolutions and maintained Takomi docs. Do not rewrite historical notes or make unrelated changes. Follow current `release/README.md` and `scripts/local-build.ts` rather than assuming old artifact names or version gates. Run focused tests and package-scoped typechecks only, never repo-wide checks. Commit the local merge and any necessary corrective commits only after relevant checks pass. Confirm `merge-base HEAD upstream/main` equals `upstream/main` and the tree is clean on success. Report blockers honestly; do not commit an unresolved merge.
>
> Always give me these optional built web/server test commands without running them: `vp run --filter t3 build` and `node apps/server/dist/bin.mjs serve --base-dir .t3/production-test`. Tell me to confirm the test directory is unused. Report original HEAD, backup, upstream/merge/corrective commits, checks, that no release artifacts were built, and unresolved limitations. Do not schedule another migration or launch a second one.
